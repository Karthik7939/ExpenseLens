# ExpenseLens

A personal expense tracking dashboard built with **React**, **TanStack Router**, **Tailwind CSS**, **FastAPI**, and **SQLite**.

The app includes a polished analytics UI for tracking expenses, viewing budget summaries, browsing charts, exporting data, and adding/removing transactions. The frontend is connected to a Python backend that persists data in SQLite.

## Features

- Expense dashboard with summary cards and analytics charts
- Add expense form with category, date, amount, and description
- Transaction table with search and delete actions
- Budget overview and export actions
- Collapsible and draggable sidebar
- Rupee-based currency display
- Python backend with SQLite persistence
- REST API for list, create, and delete expense records

## Getting Started

```bash

```

### 5. Run the frontend

```bash
npm run dev
```

The frontend will be available through the Vite dev server.

## How the App Works

The frontend is a dashboard experience that renders expense data into:

- summary cards for total spending, monthly spending, remaining budget, and top category
- bar, pie, and trend charts
- a searchable transactions table
- a form for adding new expenses
- export actions for CSV and reporting

Data is no longer hardcoded on the frontend. Instead, the app loads expenses from the backend API on startup, then sends new records to the API and deletes records through the API as well.

## Frontend Architecture

### Main route
The dashboard is implemented in `src/routes/index.tsx`.

That page:
- fetches expenses from the backend
- manages the sidebar state
- calculates spending totals and category insights
- passes the data into charts, the table, and the form

### API client
The frontend API wrapper lives in `src/lib/api.ts`.

It provides three functions:
- `fetchExpenses()` for `GET /expenses`
- `createExpense()` for `POST /expenses`
- `deleteExpense()` for `DELETE /expenses/{id}`

The API client currently points to `http://127.0.0.1:8000`.

## Backend Documentation

The backend is a small FastAPI application designed to store expense records in SQLite and expose them through a REST API.

### Backend files

- `src/backend/app.py` - FastAPI app and route definitions
- `src/backend/models.py` - SQLModel database model for expenses
- `src/backend/database.py` - SQLite engine setup and table creation
- `src/backend/requirements.txt` - backend Python dependencies

### Backend model

The `Expense` model contains:

- `id`: integer primary key generated by SQLite
- `date`: a date value stored in SQLite
- `category`: category name like Food, Transport, Bills, etc.
- `description`: optional text description
- `amount`: numeric amount spent

### Database behavior

- SQLite database file: `expense_lens.db`
- Tables are created automatically on startup through `init_db()`
- SQLModel handles the ORM layer
- `check_same_thread=False` is enabled so SQLite works correctly with Uvicorn's threaded environment

### API endpoints

#### `GET /health`
Returns a basic health check response.

Example response:

```json
{"status":"ok"}
```

#### `GET /`
Redirects to `/docs`.

#### `GET /favicon.ico`
Returns a no-content response so browser favicon requests do not produce 404s.

#### `GET /expenses`
Returns all saved expenses ordered by date descending.

#### `POST /expenses`
Creates a new expense record.

Example request body:

```json
{
  "date": "2026-05-07",
  "category": "Food",
  "description": "Lunch",
  "amount": 250
}
```

#### `DELETE /expenses/{expense_id}`
Deletes an expense by ID.

### Date handling

The backend accepts dates in ISO format (`YYYY-MM-DD`).
If the frontend sends a string, the backend converts it into a Python `date` before inserting it into SQLite.

This avoids the SQLite type error that occurs when a full datetime string is passed to a `Date` column.

### CORS

CORS is currently open for development:

```python
allow_origins=["*"]
```

This lets the frontend talk to the backend during local development.
For production, restrict this to the actual frontend domain.

## Troubleshooting

### Backend returns a date type error
Make sure the frontend sends `YYYY-MM-DD` and that you are running the current version of `src/backend/app.py`.

### Frontend cannot load expenses
Verify that the backend is running at `http://127.0.0.1:8000`.

### SQLite file is empty
The database is created on startup. Add an expense record from the UI or use the API directly.
